# Codex 通用任务合同

状态：**当前权威**

最后复核：2026-07-18

本合同定义山支度任务开始、执行、验证和报告的最低要求。它不是要求每个小任务填写长表；低风险任务可以使用简版，高风险任务必须完整记录并满足附加门槛。

全项目长期规则见 [`../AGENTS.md`](../AGENTS.md)，文档路由见 [`index.md`](index.md)。当前任务的明确指令可以增加限制，不能自行放宽安全门槛。

## 1. 先判断风险

| 等级 | 典型任务 | 最低处理方式 |
| --- | --- | --- |
| 低 | 文档、错别字、明确的日文文案、无行为变化的小型展示调整 | 简版任务说明、针对性检查、差异审查 |
| 中 | 普通Bug、组件行为、数据读取、状态管理、非核心重构 | 完整任务合同、复现或基线、相关测试、静态检查、影响面审查 |
| 高 | 数据库/RLS、生产数据、山岳火山、安全、装备清单核心规则、登录/OAuth、原生打包、部署 | 完整合同、权威来源、快照、断言、人工审批、精确回退、完整验证 |

不确定时按较高一级处理。风险等级不能用来绕过负责人明确设置的限制。

## 2. 低风险简版

普通文档、文案和确认无行为变化的小修改，只需在开始时明确：

1. 目标和修改范围。
2. 不改变的行为或内容。
3. 相关权威文档或当前页面。
4. 针对性验证方法。
5. 是否仅本地、是否允许提交；push和部署默认未授权。

完成后报告修改文件、验证结果和未执行动作。纯文档修改不要求运行build或全量测试。

## 3. 标准任务合同

中高风险任务，以及任何范围不明确的任务，开始前应明确以下内容。可以使用短句，不要求形式化表格。

### 目标

- 用户或业务最终要得到什么结果？
- 结果如何被观察或验证？

### 范围

- 允许修改的模块、文件、数据对象或环境。
- 本次是否允许本地修改、本地提交、push、合并、部署或生产执行。

### 非目标

- 本次明确不解决什么。
- 哪些相邻代码、数据或配置不得顺手整理。

### 禁止事项

- 用户、`AGENTS.md` 和专题规则明确禁止的动作。
- 无授权时默认禁止：push、部署、生产执行和敏感配置修改。

### 风险等级

- 低 / 中 / 高。
- 风险来自业务、安全、数据、兼容性、发布还是回退难度。

### 权威规则来源

- 从 [`index.md`](index.md) 选择本任务需要的文档。
- 对业务事实只读核对相关源码、测试和 migration；聊天记录或旧快照不能作为唯一依据。

### 当前基线或复现证据

- Bug：复现步骤、当前结果、期望结果。
- Bug复现后：记录能够由源码、日志或测试支持的根因；无法证明时写“根因未确认”，不把相关性当因果。
- 数据：目标行、实际slug/主键、当前值和行数。
- 文档/配置：当前冲突文字或实际生效状态。
- 无法复现时必须明确说明，不能把推测写成根因。

### 影响范围

- Web、旧版App、新版App、iOS二进制、Supabase、生产数据、缓存、认证和安全提示中哪些会受影响。
- 是否改变用户已有数据或旧版本兼容性。

### 修改计划

- 使用最小步骤说明修改顺序。
- 中高风险任务设置可停止、可验证的阶段边界。

### 完成条件

- 功能、数据、测试、人工场景和报告分别达到什么状态。
- “本地完成”与“已经上线”必须分开定义。

### 验证方法

- 针对性验证：每个修改步骤直接相关的检查。
- Bug修复：增加或更新能够覆盖原复现路径的回归测试；无法自动化时记录可重复的人工回归步骤和原因。
- 阶段验证：相关测试、lint、typecheck或受影响场景。
- 发布前完整验证：全量测试、build、人工回归、预览/真机和部署状态；仅在发布任务中执行。

### 发布授权

- 分别记录本地修改、本地提交、push、合并、部署和生产执行是否已获授权。
- 未明确授权的动作写为“未授权/未执行”，不得从上下文推定。

### 回退方式

- 代码/文档：可独立revert的提交或明确文件恢复方式。
- 数据：精确到目标行和旧值的回退SQL；不能只写“从备份恢复”。
- 原生/部署：上一可用build或部署，以及触发回退的判定条件。

## 4. 数据库任务附加门槛

数据库、RLS、schema和生产数据任务一律按高风险处理。

在任何写入前必须具备：

1. 负责人对修改范围和生产执行的明确授权；调查授权不等于写入授权。
2. 实际项目、schema、表、主键/slug、目标行数和当前值的只读基线。
3. 变更前快照，能够生成精确回退SQL。
4. 范围精确、可审查、尽可能幂等的SQL；生产默认禁止 `supabase db push`。
5. 对目标行数、允许字段、禁止字段、关键业务不变量和未触碰对象的断言。
6. 事务边界：断言失败必须阻止提交；不得先写入后再决定是否正确。
7. 提交后的独立只读复查；需要多个结果集时分别查询并保存证据。
8. 最终报告区分：migration文件、本地验证、生产执行、代码push和部署状态。

缺少快照、授权、精确范围或可执行回退时，停止在只读调查/方案阶段。

## 5. 山岳与火山数据附加门槛

山岳、火山、入山限制和安全提示由项目负责人 FUMI 最终批准。

在提出或执行修改前必须：

1. 核对生产或migration中的实际slug，不从自然语言名称猜测。
2. 区分稳定山岳资料与动态状态：长期地形/标准路线属性属于稳定层；当前火山活动、临时入山限制和复核窗口属于动态状态层。
3. 记录来源机构、原始链接/资料、观察日期和数据时效。动态信息不能写入稳定备注来冒充长期事实。
4. 对高影响结论优先使用气象厅、自治体、设施运营方等一手来源；存在来源冲突时停止并交负责人判断。
5. 明确允许修改的slug、字段和目标行数，以及禁止修改的字段和未触碰山岳。
6. 使用影响行断言和旧值快照，准备精确回退。
7. 说明对计划生成、`REVIEW_REQUIRED`、`BLOCKED`、火山提示和装备清单的影响。
8. 在任何生产执行前取得FUMI对内容和执行的双重确认。

## 6. 安全相关任务附加门槛

安全任务包括火山阻断、入山限制、装备安全规则、认证边界和可能导致用户错误判断的提示。

必须：

1. 默认采用 fail-closed：权威状态读取失败或证据不足时，不把未知状态自动解释为安全可行。
2. 分析误报和漏报：错误阻断会影响可用性，错误放行可能影响人身安全；两者必须分别说明。
3. 记录权威来源、适用范围、数据时效和人工审批人。
4. 验证旧版本、缓存、降级路径和读取失败时的行为。
5. 使用针对性测试保护关键不变量，并在发布前运行完整相关场景。
6. 不允许模型、Codex或自动化工具代替FUMI作最终安全批准。

## 7. 最终报告格式

任务结束时使用以下顺序，省略不适用项即可：

1. 结果：完成、部分完成或阻塞。
2. 修改：文件、数据对象或配置；说明是否仅本地。
3. 验证证据：命令、测试、人工场景、只读查询及结果。
4. 提交与发布：commit、push、部署、生产执行分别列出。
5. 未执行：因未授权、范围外或风险而未做的动作。
6. 回退：对应提交、SQL或上一可用版本。
7. 剩余风险和需要负责人决定的事项。
